Nada do que a admissão usa está fixo no sistema: os textos (resolução, e-mail, termo de posse e boas-vindas), os checklists de documentos e os parâmetros do módulo são editados pelo RH, em RH › Modelos e RH › Parâmetros. Exigem controle total no RH.

Cada modelo nasce com um texto padrão. Editar abre o editor, com negrito, listas, tabelas e cores:

[[m02-editor-modelo]]
  • Salvar vale para as próximas admissões. Uma admissão que já copiou o texto da resolução ou do termo continua com o dela, editável só nela.
  • Restaurar o texto padrão volta ao texto original do sistema.
  • O HTML do editor é limpo ao salvar (scripts e estilos estranhos são removidos).

Placeholders

Os textos usam placeholders, palavras começadas por # que são trocadas pelos dados da pessoa na hora de gerar o PDF ou o e-mail. A lista é fechada: qualquer outro # é recusado ao salvar, com a indicação do trecho.

[[m02b-placeholders]]
  • Se o dado não existir ainda (por exemplo, #numeroresolucao antes da reserva), o texto mostra um traço longo (—) e nunca "#nome".
  • Os valores são sempre escapados: nada digitado numa ficha vira código no PDF ou no e-mail.

Checklists de documentos

Cada checklist é uma lista de documentos que vale para uma ou várias classificações de cargo (grupo e nível, como 1.15 ou 2.10).

[[m03-checklists]]

Novo checklist (ou Editar):

[[m04-checklist-classificacoes]]
  • Em Vale para as classificações, clique nos níveis de cada grupo. O Grupo 1 é direção e chefia; o Grupo 2, assessoria. Todos e Nenhum marcam ou desmarcam o grupo inteiro. É possível marcar várias classificações (1.15, 1.16, 1.17...) no mesmo checklist.
  • Também vale para cargos sem classificação (Outros) cobre os cargos do tipo Outros.
  • É preciso marcar ao menos uma classificação ou "Outros" para salvar.
  • Cada documento pode ser obrigatório ou opcional. Só os obrigatórios travam a conclusão da etapa de documentos.
  • Ao iniciar uma admissão, os itens de todos os checklists ativos que valem para a classificação do cargo são copiados para ela, sem repetir descrições. Alterar ou excluir o checklist depois não muda as admissões em andamento.

Parâmetros: setor de apoio administrativo

Em RH › Parâmetros ganhou um campo novo: o Serviço de Apoio Administrativo (SAA), o setor que dá andamento nos números reservados do Protocolo. Antes ele era procurado pelo nome do setor no código; agora é escolhido na lista. Em branco, vale o setor de nome igual ao configurado no sistema.

[[p13-parametros-setor-apoio]]

As demais regras da tela (férias, licença-prêmio, avisos) estão na página "Para a CGP".

Para quem administra a integração com o GLPI

  • O envio do formulário de nomeação usa a tela web do GLPI (a API não envia formulários). Por isso, em Administração › Integração GLPI, há, além dos tokens, o usuário e a senha web da conta de serviço e o id do formulário "CGP - Nomeações" (padrão 8). A senha fica cifrada e nunca volta pela tela.
  • A conta de serviço precisa estar na lista de quem pode usar o formulário, em "Controles de acesso" do formulário no GLPI.
  • O formulário é lido pelo título das perguntas: se alguém renomear ou remover uma pergunta no GLPI, o SGI avisa qual pergunta mudou antes de enviar.
